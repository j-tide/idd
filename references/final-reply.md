# 最终回复模板

本轮开发或恢复执行结束时读取本文件。结论先行，使用下列固定顺序；按目标规模缩短内容，不重复粘贴执行日志。纯咨询、只读评估或仅“聊想法建 Issue”不套用开发交付报告。

## 状态与表达

- **🔵 PR / MR 待验收 / CI 运行中**：本地 TASK、验证及最终 Review 已完成并已提交 PR / MR，等待远端 CI 结束或用户验收确认。
- **🟡 待本地验收**：（纯本地无 PR/MR 模式）必要 TASK、验证及最终 Review 均已完成，列出供用户验收的工作树、需求分支和提交 SHA。
- **✅ 已完成**：约定范围、必要验证、Review、CI 检查与用户验收均已满足，且已线性合入（说明工作树/分支保留或清理情况与 `TASK/` 清理结果）。
- **🟡 部分完成**：已有独立交付，但仍有必要任务或检查未完成；列明剩余范围。
- **⛔ 受阻**：关键条件未满足（含连续两轮 CI 修复失败），当前无法继续相关工作；给出解除条件和下一步。
- **⏸️ 已暂缓 / ⏹️ 已取消**：仅用于用户明确作出的决定，说明已有工作和保留事项。
- **⚠️**：标识待处理、跳过或限制；不能当成检查通过。失败明确写“失败”，不靠图标暗示。

emoji 用于结论与需要关注的位置，避免每个条目都装饰；图标旁保留明确文字。完成数只计 `done`，分母是本 Issue 任务总数，暂缓和取消单独说明。授权范围调整后的阶段交付也应链接仍未完成的原任务，不通过缩小分母制造全部完成。

## 标准模板

```markdown
**<状态图标与结论>｜<Issue 标题（如 #42 导出 CSV）>**

<一句话说明实际结果或行为变化> **任务：<done 数>/<总数>。**

**完成内容**

- <最重要的变化及其用途>
- <其他必要变化；通常 1～3 项即可>

**验证结果**

| 任务 | 验证目标 | 实际结果 |
| --- | --- | --- |
| <TASK-XX，可链接任务文件> | <测试文件/命令/人工检查> | <通过数，或失败/部分/未执行及原因> |

- Issue 级检查：<实际运行的回归、类型检查、构建、Lint 等及结果；不适用或跳过的检查说明原因>。
- Review：<完整 Issue Diff 的实际检查结果；有遗留问题则明确列出>。

**⚠️ 待处理事项**

- <阻塞、未完成或限制；下一步和解除条件。没有此类事项时省略整段>

**交付状态**

- Issue：<#编号及链接（若有）>
- 分支与工作树：<需求分支名、工作树路径及当前状态（默认保留 / 已按需清理工作树）>
- PR / MR 与 CI：<PR/MR 链接与 CI 检查结论（若有）>
- 主线合入：<若已合入，写明 Squash 直线提交 SHA、`TASK/<issue>/` 清理情况及远端状态>
```

表格一行对应一个任务或一组共享验证的任务，保留任务到测试/检查的映射；不要逐个展开全部测试用例。长命令可在表中简写测试目标，并链接包含真实命令和结果的任务文件。小 Issue 可用一句话合并“完成内容”，仍保留进度、验证、必要限制和交付事实。

“全部任务记录为 done”不能单独证明 Issue 级检查通过。跳过全量产品测试时说明与本次改动范围的关系；没有执行构建不能写成构建通过。只做文档检查时写明实际检查，不编造测试数量。

本地提交、推送开发分支、创建 PR/MR、CI 通过、Squash 合入主线、清理工作树是不同事实，分别陈述。有 `origin` 远端时，向当前需求开发分支执行 `git push -u origin HEAD` 属于本轮常规交付步骤，不要因误解“外部操作”而跳过推送开发分支；不要把“已提交”写成“已合入”，也不要为了填齐交付状态而擅自执行合入 `main`、强推共享历史、发版或部署等未授权操作。链接应指向用户能访问的实际文件/产物；本地文件在回复中使用绝对路径。

## 受阻时的写法

例如连续两轮 CI 修复未通过或缺少真实联调凭据时，结论可写：

```markdown
**⛔ 受阻｜#44 飞书 Webhook 通知**

已完成适配器骨架与本地 Mock 回归，因缺少真实签名密钥无法完成线上联调校验。**任务：1/2。**

**验证结果**

| 任务 | 验证目标 | 实际结果 |
| --- | --- | --- |
| TASK-01 | 签名生成与本地单测 | 已通过；具体命令与证据见任务文件 |
| TASK-02 | 真实 Webhook 联调及 CI 集成测试 | 未执行/失败：缺少测试凭据；已按上限停止自动重试 |

- Issue 级检查：本地单测与 Lint 通过；端到端联调未完成。
- Review：已完成当前 Diff 核对，不能据此宣称真实渠道可用。

**⚠️ 待处理事项**

- 解除条件：提供测试环境 Webhook 地址与签名密钥后，通过 `idd start 44` 回到原工作树继续 `TASK-02`。

**交付状态**

- Issue：#44（进度已通过 `idd sync` 同步）
- 分支与工作树：`feat/44-webhook` 保留于工作树，待解除阻塞后继续
- PR / MR 与 CI：暂未创建（或列出 PR/MR 链接与失败 Job/Run ID）
```

示例数字只用于展示结构，实际回复必须替换成当前任务事实。用户偏好更精简或另有输出格式时，保留必要事实并遵从其明确要求。
