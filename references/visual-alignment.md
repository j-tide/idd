# 直观原型对齐规范（Show, Don't Just Tell）

在「聊需求 → 建单 / 动代码」之间增加轻量的直观对齐门禁，避免仅靠文字描述拍板导致开发完成后再大幅返工。本规范保持流程轻量：**不写厚重 PRD / Design 文档**，只展示最能暴露布局、交互与边界问题的一手样例。

## 一、按改动类型分级的预览标准

| 改动类型 | 动代码前必须给出的「直观预览」 | 禁止行为 |
| --- | --- | --- |
| **UI / 页面 / 交互 / 看板** | **可点击的轻量交互原型（单文件 HTML）**，内置状态切换按钮（正常态 / 空态 / 加载态 / 报错态 / 超长文本） | 仅用文字描述排版，或贴静态线框 ASCII 图代替真页面效果 |
| **CLI / 终端输出 / 报告 / 接口格式** | **1:1 真实样例的 Before vs After 对比**（完整命令输出、表格对齐、JSON 结构、报错文案） | 只说“优化排版”“字段更清晰”而不给出实际渲染样例 |
| **状态机 / 多分支流程 / 协作逻辑** | **Mermaid 流程图 / 状态图 + 边界场景对照表**（正常、失败、重试、取消、并发时分别怎样） | 只列文字步骤而忽略异常分支与回退路径 |
| **明确 Bug 修复 / 纯内部重构** | **豁免原型**：只给极简「复现输入 → 修复后预期输出（Before/After）」+ 影响面清单 | 为简单单点 Bug 过度设计原型 |

## 二、多工具呈现与本地预览

- **Antigravity**：优先直接发布可交互 HTML Artifact（如 `publish_artifact`），让用户在浏览器内直接点击、切态、看布局。
- **Claude Code / Codex / 本地终端**：将临时原型写入**仓库外临时目录**（如 `/tmp/idd-preview/`），调用 `idd preview` 启动本地热更新预览工作台并附上访问地址：
  ```bash
  # 单文件预览（保存即自动热更新）
  idd preview /tmp/idd-preview/board.html

  # 多方案 A/B 并排对比（支持自定义 `标签=路径` 与桌面/平板/手机视口切换）
  idd preview 方案A=/tmp/idd-preview/plan-a.html 方案B=/tmp/idd-preview/plan-b.html --compare

  # 监听整个临时原型目录（新增 .html 自动出现在标签栏）
  idd preview /tmp/idd-preview/
  ```
- **严禁污染业务仓库**：所有事前原型均属于临时对齐产物，**不得提交进项目 Git 仓库**。

## 三、原型与样例必查的边界态清单

出原型或样例时，按实际相关性显式覆盖以下状态（UI 原型建议内置顶部或侧边切换按钮）：

1. **空态（Empty）**：无数据、首次使用或搜索无结果时如何提示与引导下一步。
2. **报错与受阻态（Error / Blocked）**：请求失败、权限不足、文件缺失或校验不通过时的文案与恢复入口。
3. **加载 / 异步过渡态（Loading）**：长耗时操作是否有反馈，避免假死或重复点击。
4. **极端内容（Overflow / Edge）**：超长标题、多行换行、窄屏/手机视口下的折行与截断是否破坏布局。
5. **关键状态转换（Transitions）**：并发冲突、重试上限、取消操作后的最终一致状态。

## 四、定稿沉淀与薄切片早验收

1. **先收敛取舍，再出原型**：需求存在多种做法时，先用 2~3 个具体取舍点对齐方向，再直接生成可看/可点的样例。
2. **确认后固化进 Issue 验收标准**：用户对原型或样例拍板后，将确认的视觉结构、交互路径与关键边界态写成 Issue 的 `- [ ]` 验收标准，确保跨工具接手不跑偏。
3. **UI / 交互任务的薄切片早验收（Early Visual Checkpoint）**：
   - 在 `TASK` 拆解时，高视觉或高交互需求应让 `TASK-01` 优先跑通**最小可交互真页面 / 主链路**；
   - `TASK-01` 完成后先让用户看真效果、确认手感与版式无误，再继续补齐边缘逻辑与全量自动化测试。
